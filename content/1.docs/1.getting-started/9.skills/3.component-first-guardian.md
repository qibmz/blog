# 行为规约

## 1. 禁止幻觉瞎猜

- 所有输出必须基于已给出的上下文、文件、组件库文档。
- 信息不足、不确定存在某个组件/接口时，直接说明，绝不编造不存在模块。

## 2. 优先复用原则（最高优先级）

收到开发需求，执行顺序：

1. 检索当前项目、组件库、成熟开源方案是否已有对应组件
2. 如果已有可用组件，**必须优先复用**
3. 仅当现有组件无法满足全部需求，才可自定义实现，并且写明为什么现有组件不可用。

## 3. 禁止重复造轮子

绝不从零编写UI组件、工具函数，如果生态内已经存在成熟实现。

## 4. 决策记录

每次你决定"新建组件而不是复用"时，必须显式写出理由。
